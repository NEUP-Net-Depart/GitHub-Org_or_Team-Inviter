## 1. 砍掉 `.txt` 名单与标准输入(用户提出)

**用户**: 「我觉得没必要搞 .txt 的, 业务逻辑太臃肿了, 只要 xlsx 和 csv 的」

理由比"臃肿"更硬: 一行只有一个字段, **装不下「邮箱 + 用户名」**。于是只有用户名的人
发不了邮箱邀请, 只有邮箱的人进不了 team —— 这个入口从一开始就带着两个能力缺口;
而且它需要自己一套解析语义(跳过 `#` 注释、只取第一个字段、逐行判邮箱还是用户名),
同一件事两套规则正是最容易长 bug 的地方。

删掉: `_rows_to_records()`、`.txt`/stdin 分支、`looks_like_file()` / `looks_like_path()` /
`_declared_as_identity()`(它们只为「位置参数既可能是文件又可能是用户名」这个歧义服务 ——
现在第一个位置参数必须是表格文件, 歧义消失)。`read_table` 遇到 `.txt` **明确报错并指向表格**,
不静默改变行为。代码 1986 行减到 1625 行。

**一处我没照做**: 用户说「用户名和邮箱不可或缺」。我改成**每行至少有其中一个即可** ——
强求两个都有会让「只有邮箱」这条唯一能用邮箱邀请的路消失。这条跟用户确认了。

## 2. 新增 `--skip-rows`; 顺带发现一个静默出错的隐患

用户的表是 `提交时间|GitHub用户名|邮箱|姓名|备注`, 问能不能写
`--cols "-,username,email,name,-"`。能写 —— 但顺着这个问题测出一件更糟的事:

**表头认不出来时, 脚本会静默按「第1列用户名、第2列邮箱」兜底。** 实测一张
`日期|QQ|微信|怎么称呼|备注` 的表因此**把表头当成人、把真人当重复丢掉, 还返回退出码 0**:

```
列映射: 邮箱=<第 2 列>  用户名=<第 1 列>       <- 静默兜底
解析到 3 行数据, 排除 1 行                     <- 真人被当重复丢掉
  ! 第 1 行: 邮箱列里写的不是邮箱, 当用户名用了: QQ
退出码: 0                                       <- 还说自己成功了
```

加了保险: 没给 `--cols` 且超过一半记录的邮箱列都「不是邮箱」-> `die` 并给出该用的
`--cols` 示例。这是脚本里唯一一次主动拦停, 因为按错列发邀请会真的打扰到人。

## 3. `--cols` 不再关掉表头识别(用户问出来的)

**用户**: 「表里有表头时还要加 --skip-rows 1, 为什么基础命令不要加?」

**这个问题问对了。** 基础命令不用加, 是因为没给 `--cols` 时会去找表头; 给了 `--cols`
后表头识别被整个跳过 —— 于是「有表头 + 列名认不出」的表没有干净写法。

但「哪一列是什么」和「哪几行是数据」本来就是两件独立的事, 不该对立。拆成两步:

| 步骤 | 决定什么 | 依据 |
|---|---|---|
| ① 定列 | 哪一列是邮箱/用户名/姓名 | `--cols` / 表头关键字 / 位置兜底 |
| ② 定数据行 | 哪几行是数据 | `--skip-rows` / `--no-header` / 自动认出的表头 |

于是**表头认得出来时, 加不加 `--cols` 都会自动跳过表头行**。

## 4. 表头认不出来时问用户(用户提出)

**用户**: 「等认不出来的时候, 脚本直接问从哪行扫描到哪行就行……也再问一遍用户,
然后用户在格式化回答就行」

实现了两句提问, 回答格式与 `--cols` 一致:

```
表格前 3 行...         <- 让人指出数据从哪行开始
这一行数据长这样...     <- 让人指出哪一列是什么
列的顺序(直接回车 = 按老约定: 第1列用户名、第2列邮箱):
数据行范围(例如 2 或 2-10, 写 0 表示全是数据):
```

**非交互环境绝不静默挂住**: `_stdin_is_interactive()` 为假时直接 `die`, 并给出两条出路。

## 5. 删除参数这件事, 用户叫停了 —— 我同意保留

我一度按用户思路真的动手删 `--skip-rows` / `--no-header`, 改到一半用户说「那就不删了吧」。
我恢复后**没有只是照办, 而是说明了为什么该留**:

| 参数 | 非交互场景下为什么需要 |
|---|---|
| `--no-header` | **最关键**。没有它, 一张没有表头的表**没法在脚本里跑**, 只能等人回答 |
| `--skip-rows` | 认不出的表头一行, 非交互时没法回答提问, 必须靠它 |

实跑处理用户那张表用的就是 `--cols "-,username,email,name,-" --skip-rows 1`。

> **流程教训**: 我应该在动手删之前就把"删了会失去什么"摆出来 —— 用户是先说了"不删了"
> 才看到代价的。好在改动没提交, 恢复成本低。

## 6. 这一轮自己引入并修掉的 bug

### 6.1 `--skip-rows 1` 少一行数据(自己造的)

把 `first_data` 算成**相对 `rows`(已砍掉 skip 行)** 的偏移, 却又拿它去切 `rows`,
**等于跳了两次**: `--skip-rows 1` 在 3 行表上只解析出 1 条(应该 2 条)。

这个 bug **只在「`--skip-rows` + 自动认表头」同时存在时出现**, 不做这次重构就不会有 ——
是新代码引进的。现在统一用绝对偏移 `data_offset`(相对整张表), 切片时再减掉 skip,
并有一条测试专门盯行数。

### 6.2 `parse_row_range("-5")` 解析成 `5-`

我先 `strip("-")` 再合并连字符, 前导 `-`(表示"从第 1 行开始")被吃掉了。
现在先单独记住 `starts_at_first` 再处理。

### 6.3 测试环境: 非交互路径根本测不到

测试子进程**继承了终端的伪终端**, `sys.stdin.isatty()` 变成真, 于是脚本真的停下来等人回答,
**测试套件卡在提问上**。改用 `stdin=subprocess.DEVNULL` —— **还是 True**。

实测结论(Windows 特有):

```
DEVNULL        -> isatty= True    <- NUL 是字符设备!
PIPE(空输入)    -> isatty= False   <- 这个才对
继承(不指定)     -> isatty= True
```

必须用 `input=""`(即 PIPE)才能切断。这条已写进 ARCHITECTURE, 免得下次再踩。
